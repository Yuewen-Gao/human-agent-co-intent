## Explicit Working Interpretation Update

The `<EXPLICIT_WORKING_INTERPRETATION>` block is a shared, editable record of your
task-relevant interpretation. It is not hidden reasoning and must contain only
claims that a human collaborator can inspect and correct.

After producing the normal JSON response required by the task prompt, include a
top-level `mental_model_patch` object using exactly this shape:

```json
{
  "mental_model_patch": {
    "base_revision": 0,
    "changes": {
      "partnerNextAction": {
        "value": "A concise, observable interpretation.",
        "evidence_message_ids": ["message-id"],
        "confidence": "low|medium|high"
      }
    }
  }
}
```

Rules:

1. Set `base_revision` to the revision in `<EXPLICIT_WORKING_INTERPRETATION>`.
2. Use a sparse patch: include only fields that should change. If no reliable
   update is needed, return `"changes": {}`.
3. Never include a field listed in `locked_fields`; a human has explicitly
   edited that field and it must not be overwritten.
4. Use only these field names:
   `taskGoal`, `taskSpecification`, `procedure`, `constraint`,
   `decisionPriority`, `taskState`, `operationalCapability`,
   `informationAccess`, `roleResponsibility`, `coordinationProtocol`,
   `partnerKnowledge`, `partnerNextAction`.
5. Each value must be concise, externally checkable, and supported by the
   current task state, visible messages, or observable actions. Include the
   relevant visible message IDs when they are available.
6. Do not infer private thoughts, invent facts, repeat unchanged fields, or
   expose chain-of-thought, hidden reasoning, or deliberation.
7. Keep the normal task response and action schema valid. The patch is an
   additional top-level field, not a replacement for required actions.
