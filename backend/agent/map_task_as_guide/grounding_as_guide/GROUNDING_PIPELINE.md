# Map Task Grounding Pipeline

`grounding_analysis/` is an offline-only project. It produces candidate examples, but the running backend never imports or executes it.

The online backend reads three static snapshots under `agent/prompts/mapTaskGuidePrompts/groudingPrompts/`: `h_fewshots.json` supplies reviewed H examples, `repair_fewshots.json` supplies reviewed single-R repair references, and `repair_retrieval_associations.json` supplies H+W→R, H→R, and W→R support counts exported offline from the original annotations. For each `grounding_unit_no`, that export unions all H, W, and R labels on Guide actions before counting co-occurrence. Runtime loaders strip audit metadata, timestamps, future turns, Guide-authored focal responses, uptake/outcome records, and quality metadata before prompt injection. Only observable conversation/map context, a labeled mechanism, repair structure, and a historical reply excerpt cross the runtime boundary.

The orchestrator diagnoses `H` and multi-label `W` in parallel. `H1`–`H6` are operational repair triggers; `W` enriches retrieval but does not suppress a concrete H diagnosis when no W is selected. `H7` keeps the ordinary Guide path; when a fresh trajectory visibly completes the active segment, its handoff directs that path to give the next segment. `ordered_route_cells` remains start-to-end Guide-coordinate evidence: for a route-relevant H3/H5 map difference, H must reconstruct the uncompleted segment and emit a Follower-local target plus a final-segment/end completion criterion. The repair call treats those H fields as binding and must not reuse the old Guide-coordinate direction. W1 is used when a completion claim lacks final ordered-segment/end evidence. The repair call receives only each selected W definition paragraph, its observable proposition, and the alignment needed; it does not receive the full W codebook. R codes organize wording and sequence only, never route selection, map-coordinate translation, or completion criteria. When repair is needed, offline support counts only rank reviewed repair examples; no counts, probabilities, or prescribed R choice enter an LLM prompt. One subsequent LLM call selects and realizes an ordered immediate repair sequence, any deferred R7, and the reply from those H/W facts, retrieved structures, and the complete rendered Guide prompt. The current Guide grid and Follower workspace/trajectory are the authoritative task facts; retrieved examples are never a source of current landmarks or directions.

The pipeline records only inspectable evidence and structured labels. A drawing-triggered H result also records an internal trajectory verdict: `incorrect` requires a natural-language correction with one landmark-relative positional error; a completed `correct` trace hands off to the normal Guide for the next segment. These labels are not shown verbatim to participants. Correct-but-incomplete and `insufficient_evidence` traces preserve the existing instruction and send no message. A stable signature of verdict, immediate route, and expected target suppresses repeated drawing replies that would give the same advice. It does not request hidden reasoning. R7 is deferred until its specified future observable trigger occurs; it is not drafted in the same reply as a new correction. If H is `H7`, a plan is invalid, or a draft is invalid, it returns no repair rather than guessing.
